# About the Author

My name is Jon Leithe. This repository contains my personal website and the
public-facing home of my long-term engineering notebook, Project Polaris.

## Professional background

I work as a Systems Engineer at the Norwegian Mapping Authority (Kartverket),
with a focus on scientific infrastructure, precision measurement systems, and
Linux-based technical environments.

My professional experience includes:

- scientific infrastructure;
- very long baseline interferometry (VLBI);
- global navigation satellite systems (GNSS);
- hydrogen masers;
- Linux systems and automation;
- Python and C++;
- electronics and instrumentation.

## Academic context

In August 2026, I begin a part-time, online Master of Science in Aerospace
Engineering at UiT Narvik. Project Polaris supports those studies by bringing
together course notes, worked examples, references, diagrams, software, and
technical explorations.

The academic source material belongs in the adjacent
`project-polaris-academy` repository. This website should present selected
material without becoming a second source of truth for it.

## Purpose of the website

The website should provide a clear, professional introduction to who I am and
what I work on. Over time, it may include:

- an About page;
- selected engineering and academic notes;
- software and electronics projects;
- a curriculum vitae;
- technical articles and demonstrations.

The intended audience includes engineering students, technical colleagues,
future employers, and others interested in scientific infrastructure and
engineering practice.

## Design and writing preferences

I prefer a site that is:

- restrained, readable, and technically professional;
- personal without being overly decorative;
- easy to maintain and reproduce;
- useful in both light and dark themes;
- built from simple components with minimal dependencies.

Writing should be direct, precise, and approachable. Technical material should
explain why something works, introduce notation carefully, and connect theory
to practical engineering where appropriate.

## Development environment

My primary environment is:

- Arch Linux;
- VS Code;
- Kitty with Bash;
- Hyprland;
- Git for version control.

The website uses Hugo with the PaperMod theme. Deployment is to One.com over
SFTP. Quarto is used in the Academy repository for multi-format note rendering.

## Working principles

My priorities are:

1. correctness over speed;
2. readability over cleverness;
3. maintainability over shortcuts;
4. reproducible builds;
5. automation where it provides lasting value;
6. small, focused changes with meaningful version history.

Inspect existing work before editing, preserve unrelated changes, and never
publish or deploy without an explicit request.
